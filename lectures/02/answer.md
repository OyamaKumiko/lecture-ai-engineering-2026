## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：
  - num_train_epochs を20から10に変更。lr（2e-4）と lora_r（16）は元のまま。変えたあとはセッションを再起動して、上から実行し直した。
- 結果（比較表や数字）：
  | | epochs 20（元の設定） | epochs 10 |
  |---|---|---|
  | ステップ数 | 40 | 20 |
  | 最終 loss | 0.0139 | 0.0985 |
  | 学習時間 | 231 秒 | 116 秒 |
  | format_rate（学習後） | 1.0 | 1.0 |
  | content_rate（学習後） | 0.905（19/21） | 0.857（18/21） |
  | 退行 | なし | なし |
  - 学習時間はほぼ半分になり、形式は 10 エポック（20 ステップ）でも全問守れた。
  - content_rate は 1 問分の差だったが、失敗した問題は入れ替わっていた。
    - epochs 20 のみ失敗：「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」（どちらも断定）
    - epochs 10 のみ失敗：「PDF 以外でも出せますか」（FAQ にあるのに「記載がありません」と返した）、「課題の文字数に制限はありますか」「参考文献の書き方に指定はありますか」（needs_review は true だが、answer に「確認」の語が無く、内容の判定で ×）
  - epochs 10 では文面が崩れた。確認を求める文が「必ず確認が必要です」「必ずに確認が必要です」のようになり、教師データの文（「運営に確認が必要です」）を覚えきれていなかった。
  - 知識を問う質問の分類は、2回とも同じだった。「最終課題の締切」を提出期限の文で断定する失敗は、どちらでも残った。
  - seed を固定しても GPU 上の学習は完全には再現しないので、1 回ずつの結果から「エポック数を減らすと必ずこうなる」とは言えない。
- ファインチューニングが向く場面・向かない場面についての考察：
  - 向きそうな場面：出力の形（今回は JSON の 2 つのキー）や、決まった文面で答えさせたいとき。プロンプトで指示しても守れなかった形式が、数分の学習で揃ったため。
  - 向かなさそうな場面：「根拠があるかどうか」の判断や、内容の正しさを保証したいとき。今回は断定の失敗が学習後も残り、エポック数を変えても直らなかった。また、FAQ の内容が変わるたびに学習し直す必要がある。
  - ただし、これは 5 項目の架空 FAQ と 1 つの小さなモデルでの結果であり、一般論ではなく今回のデータで確かめた範囲の話となる。
